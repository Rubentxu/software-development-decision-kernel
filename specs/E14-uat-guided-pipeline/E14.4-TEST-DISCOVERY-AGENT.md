# Spec: E14.4 — Test Discovery Agent (Fara → Discovered UAT)

## Goal

Usar Fara (Computer Use Agent) y Playwright para explorar una aplicación web corriendo, descubrir los flujos de UI reales, y generar un "Actual Application Model" que alimente al ScenarioAgent con flujos descubiertos (no inventados).

## Concepto

El Test Discovery Agent no取代 al ScenarioAgent. Lo informa. El agente decide qué flujos son relevantes basándose en:
1. Los requisitos (requirements)
2. Lo que la UI real ofrece

Ejemplo: requisito "A user can delete a workspace" → el agente descubre:
```
Workspace list
  → Click "..." menu on workspace item
    → Dropdown with "Delete" option
      → Confirmation modal appears
        → User types workspace name
          → Delete button activates
            → Redirect to /workspaces with success message
```

Este flujo real se convierte en un scenario UAT con steps descubiertos (no imaginados).

## Arquitectura de discovery

```
┌─────────────────────────────────────────────────────────────┐
│ Test Discovery Agent                                        │
│                                                             │
│  1. EXPLORE (Fara CUA)                                     │
│     - Receives: goal description + app URL                 │
│     - Fara navigates, clicks, types — discovers UI flows  │
│     - Captures: screenshots, DOM snapshots, URL diffs   │
│     - Output: list of discovered flows with trajectory     │
│                                                             │
│  2. MODEL (Playwright + Fara)                             │
│     - Playwright inspects DOM state post-action           │
│     - HTTP calls observed via devtools                    │
│     - Screenshot captured at each step                     │
│     - Output: Actual Application Model (AAM)              │
│                                                             │
│  3. GENERATE (ScenarioAgent integration)                  │
│     - AAM → UatScenario[] con plain_steps + form specs   │
│     - Respects existing requirements coverage             │
│     - Skips redundant/discovered flows                   │
└─────────────────────────────────────────────────────────────┘
```

## Actual Application Model (AAM)

```yaml
actual_application_model:
  version: 1
  discovered_at: "2026-08-11T..."
  app_url: "http://localhost:3000"
  exploration_session_id: "fara-..."

  pages:
    - path: /login
      title: "Login"
      elements:
        - selector: "#email"
          role: textbox
          label: "Email"
        - selector: "#password"
          role: textbox
          label: "Password"
        - selector: "button[type=submit]"
          role: button
          label: "Sign in"

    - path: /workspaces
      title: "Workspaces"
      elements:
        - selector: "[data-workspace-list]"
          role: list
        - selector: "[data-create-workspace]"
          role: button
          label: "Create workspace"

  flows:
    - id: flow-1
      title: "User login"
      pages: [/login]
      steps:
        - action: navigate
          target: /login
        - action: fill
          selector: "#email"
          value: "user@example.com"
        - action: fill
          selector: "#password"
          value: "secret"
        - action: click
          selector: "button[type=submit]"
        - action: wait_for_url
          expected: "/workspaces"

    - id: flow-2
      title: "Create and delete workspace"
      pages: [/workspaces]
      steps:
        - action: navigate
          target: /workspaces
        - action: click
          selector: "[data-create-workspace]"
        - action: wait_for
          selector: "[data-create-modal]"
        - action: fill
          selector: "[data-workspace-name]"
          value: "UAT Test Workspace"
        - action: click
          selector: "[data-create-submit]"
        - action: wait_for
          selector: "[data-workspace-item]"
```

## Discovery Strategies

### 1. Goal-directed exploration
- Input: requirements list
- Fara recibe: "Explora todas las formas de crear/borrar/editar recursos en esta app"
- Output: flujos descubiertos con screenshots

### 2. Sitemap crawl
- Input: starting URL + max depth
- Playwright crawls sitemap o Discovery paths
- Output: pages + navigation structure

### 3. API traffic observation
- Input: app URL + auth token
- Proxy/observe HTTP calls
- Output: API endpoints + request/response shapes

## Integration con pipeline

```
Requirement
    ↓
┌─────────────────┐
│ DiscoveryAgent  │ ← E14.4: Explora app real
└────────┬────────┘
    ↓  (AAM + discovered flows)
┌─────────────────┐
│ ScenarioAgent   │ ← uat-planner: Usa flows descubiertos
└────────┬────────┘
    ↓
... (resto del pipeline E14.5)
```

El AAM se guarda en:
`~/.local/share/sddk/projects/<id>/artifacts/aam-<session_id>.yaml`

El agente guarda provenance:
```yaml
provenance:
  generated_by: uat-discovery
  exploration_session: fara-<uuid>
  discovered_by: Fara CUA + Playwright
  based_on:
    requirements: [REQ-001, REQ-002]
    app_url: http://localhost:3000
  confidence: 0.78
  human_reviewed: false
```

## Implementation

### Location
- **Agent**: `agents/uat-discovery.md` — el agente propiamente dicho
- **Skill**: `skills/uat-discovery/SKILL.md` — orquestación
- **Driver**: `assets/uat-driver/discovery.mjs` — script que ejecuta Fara + Playwright en loop
- **CLI**: `sddk uat discover --app-url URL --requirements FILE [--output aam.yaml]`

### Prerequisites

- Fara corriendo en `http://localhost:8082` (ComputerUseExecutor)
- Playwright instalado y configurado
- App bajo test corriendo con acceso local

## Acceptance Criteria

- [ ] `sddk uat discover --app-url http://localhost:3000` produce un AAM válido
- [ ] El AAM incluye: pages[], elements[] (con selectors y roles), flows[] (con steps)
- [ ] Los flows descubiertos incluyen screenshots de cada paso
- [ ] El agente detecta cambios de URL, aparición de elementos DOM, y HTTP calls
- [ ] El output es consumible por uat-planner para generar scenarios basados en flujos reales
- [ ] Si Fara no está disponible, el agente emite error con instructional message
- [ ] El AAM generado pasa validación de schema
