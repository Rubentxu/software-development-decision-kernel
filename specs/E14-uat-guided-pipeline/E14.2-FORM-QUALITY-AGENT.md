# Spec: E14.2 — Form Quality Agent (Anti-Test-Smells)

## Goal

Implementar el Form Quality Agent que analiza specs de UAT contra el catálogo de test smells en tests manuales escritos en lenguaje natural (arXiv:2308.01386) y emite advertencias accionables antes de publicar el UAT.

## Catalog of Test Smells (arXiv:2308.01386 + extensiones)

El agente detecta estas categorías de smells:

### Estructurales
| Smell | Descripción | Ejemplo |
|-------|-------------|---------|
| `AMBIGUOUS_INSTRUCTION` | La instrucción no dice exactamente qué hacer | "Abre el proyecto" sin indicar URL o acción exacta |
| `EXPECTED_ABSENT` | No hay expected result definido | Step sin `expected` ni `check` |
| `MACHINE_OBSERVABLE` | Se pide al humano observar algo que la máquina verifica | "¿La API devolvió 200?" cuando hay un oracle HTTP |
| `DUPLICATED_CHECK` | Dos checks verifican lo mismo | Dos checks HTTP idénticos en el mismo step |
| `NO_RECOVERY_PATH` | No hay acción de recovery si falla | Step sin `on_fail` ni checkpoint de diagnóstico |

### Cognitivos
| Smell | Descripción | Ejemplo |
|-------|-------------|---------|
| `LEADING_QUESTION` | La pregunta guía hacia una respuesta | "¿No es verdad que el modal abre correctamente?" |
| `SUBJECTIVE_NO_SCALE` | Criterio subjetivo sin escala | "¿Es fácil de usar?" sin rating 1-5 |
| `FAIL_NO_EVIDENCE` | FAIL sin evidencia obligatoria | `evidence.required: false` en un check crítico |
| `STEP_TOO_LARGE` | Step con >5 sub-acciones | "Abre settings, busca integrations, conecta GitHub, configura webhook, guarda" |

### UX/Dinámicos
| Smell | Descripción | Ejemplo |
|-------|-------------|---------|
| `EXCESSIVE_STEPS` | Scenario con >12 steps sin checkpoint | Plan sin checkpoints intermedios en flujo largo |
| `HIDDEN_PREREQUISITE` | Prerrequisito no mencionado en preconditions ni en el step | Usa una variable de entorno que no se declara |
| `NO_BRANCHING` | Scenario sin branching pese a tener condiciones de error obvias | Modal de error sin `on_fail: goto diagnose` |
| `BLIND_CHECK_WITHOUT_HIDDEN` | `blind_observation` declarado pero `visibility` no es `hidden` | Contradicción en la spec |

## Agent Design

### Input
- Una `UatFormSpec` o lista de scenarios con sus `UatFormItem`s

### Output
- `UatFormQualityReport` con array de `TestSmell`:
  ```typescript
  interface TestSmell {
    smell_id: string;       // e.g. "AMBIGUOUS_INSTRUCTION"
    severity: "BLOCKER" | "WARNING" | "SUGGESTION";
    location: {
      feature_id: string;
      scenario_id: string;
      item_id?: string;     // si el smell está en un item específico
      step_index?: number;  // si está en un step
    };
    description: string;    // "Instruction 'Abre el proyecto' is ambiguous"
    suggestion: string;     // "Add explicit URL: http://localhost:3000/projects"
    oracle_hints?: string[]; // qué oracles automáticos podrían reemplazar esto
  }
  ```

### Algorithm

Cada smell se detecta con heuristics concretas (sin LLM para la detección estructural; LLM solo para la detección de leading questions):

1. **AMBIGUOUS_INSTRUCTION**: Regex sobre `action` buscando patrones vagos (`el proyecto`, `la sección`, `el menú`) sin URL ni label específica
2. **EXPECTED_ABSENT**: Item.kind == `check` sin `check.expected` ni `check.oracle`
3. **MACHINE_OBSERVABLE**: Question contiene strings como `API`, `HTTP`, `status code`, `response` mientras existe un oracle HTTP/JSON en el mismo step
4. **DUPLICATED_CHECK**: Mismo `oracle` + mismo `expected` en dos items consecutivos
5. **LEADING_QUESTION**: LLM evalúa si la question contiene sesgo (pattern matching con coaching phrases)
6. **SUBJECTIVE_NO_SCALE**: kind == `human_observation` o `human_confirmation` sin escala ni `require_comment_below`
7. **FAIL_NO_EVIDENCE**: kind == `check` con `on_fail` pero sin `evidence.required: true`
8. **STEP_TOO_LARGE**: `action` contiene más de 3 verbos de acción separados por "y" o ","
9. **EXCESSIVE_STEPS**: Scenario con >12 items sin ningún `checkpoint`
10. **HIDDEN_PREREQUISITE**: Referencias a variables de entorno o config en `action` sin estar en `preconditions`
11. **NO_BRANCHING**: Scenario con >3 steps con outcomes de error obvios (modal, error message) pero sin `flow: goto` en ningún item
12. **BLIND_CHECK_WITHOUT_HIDDEN**: Item.kind == `blind_observation` pero `visibility !== 'blind'`

## Implementation

### Location
- **Agent**: `agents/uat-form-quality.md` — el agente propiamente dicho
- **Skill**: `skills/uat-form-quality/SKILL.md` — orquestación del skill
- **Domain**: `crates/sddk-domain/src/uat.rs` — tipos `UatFormQualityReport`, `TestSmell`
- **CLI**: comando `sddk uat quality --plan FILE [--threshold BLOCKER|WARNING]` que invoca el agente y emite el report

### Integration

El Form Quality Agent se invoca:
1. Post-uat-planner, pre-publicación: `sddk uat quality --plan uat-plan.yaml`
2. Dentro del pipeline E14.5 (pipeline wiring) antes de `SchemaValidator`

## Acceptance Criteria

- [ ] Detecta las 12 categorías de smells listadas arriba
- [ ] Severity assignment es correcto: BLOCKER para EXPECTED_ABSENT, FAIL_NO_EVIDENCE; WARNING para AMBIGUOUS_INSTRUCTION, STEP_TOO_LARGE; SUGGESTION para NO_BRANCHING, DUPLICATED_CHECK
- [ ] El report es accionable: cada smell tiene `suggestion` con remediation concreta
- [ ] `sddk uat quality --plan FILE` devuelve exit 0 con WARNING/SUGGESTION, exit 1 solo con BLOCKER smells
- [ ] El agente NUNCA modifica el plan; solo emite el report
