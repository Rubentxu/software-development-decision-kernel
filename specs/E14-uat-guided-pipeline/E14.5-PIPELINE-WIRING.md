# Spec: E14.5 — Pipeline Wiring (All Agents)

## Goal

Integrar todos los agentes de E14.2, E14.3, E14.4 con los agentes existentes (uat-planner, uat-guide, uat-runner) en un pipeline coherente de generación asistida por IA. El pipeline va desde un requirement hasta un UAT publicado con approval humano.

## Pipeline Architecture

```
REQUIREMENT INPUTS
    │
    ├── Requirement docs (markdown/ADR/spec)
    ├── Changelog (diff desde last release)
    ├── Existing UAT plan (para regresión)
    └── Actual Application Model (E14.4, opcional)
            │
            ▼
┌──────────────────────────────────────────────────────────┐
│ STAGE 1: Scenario Generation                            │
│                                                          │
│  uat-planner                                            │
│  ├── Recibe: requirements + changelog + last plan      │
│  ├── Ejecuta: coverage analysis                        │
│  ├── Descubre gaps (vs. last plan)                     │
│  ├── Usa AAM si está disponible (E14.4)               │
│  └── Output: uat-plan-draft.yaml (escenarios candidatos)│
└──────────────────────────────┬─────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────┐
│ STAGE 2: Form Enrichment                               │
│                                                          │
│  uat-ux-form-agent (E14.3)                            │
│  ├── Recibe: scenario candidates con criterion text    │
│  ├── Decide: optimal interaction per scenario          │
│  │         (blind vs. machine vs. human)              │
│  ├── Añade: UatFormSpec por scenario                  │
│  └── Output: uat-plan-form-enriched.yaml              │
└──────────────────────────────┬─────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────┐
│ STAGE 3: Quality Gate                                 │
│                                                          │
│  uat-form-quality-agent (E14.2)                        │
│  ├── Recibe: enriched plan                            │
│  ├── Detecta: test smells (12 categorías)            │
│  ├── Emite: UatFormQualityReport                     │
│  ├── Si BLOCKER smells: stop + remediation request   │
│  └── Output: quality-report.yaml + (stop o continue)│
└──────────────────────────────┬─────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────┐
│ STAGE 4: Schema Validation                             │
│                                                          │
│  validate_form_dsl() (domain)                         │
│  ├── Recibe: plan con form specs                     │
│  ├── Valida: vocabulario cerrado del DSL v3         │
│  ├── Rechaza: specs fuera del vocabulario            │
│  └── Output: validated-plan.yaml (o error)           │
└──────────────────────────────┬─────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────┐
│ STAGE 5: Human Approval                                │
│                                                          │
│  Reviewer (humano via guided dashboard)               │
│  ├── Ve: scenarios + quality report + coverage       │
│  ├── Aprueba: escenarios individuales o el plan entero│
│  ├── Edita: inline en el dashboard (modo Designer)   │
│  └── Output: approved-plan.yaml                       │
└──────────────────────────────┬─────────────────────────┘
                               │
                               ▼
┌──────────────────────────────────────────────────────────┐
│ STAGE 6: Published UAT                                │
│                                                          │
│  uat-plan.yaml (canonical)                             │
│  ├── Provenance completo en cada scenario            │
│  ├── Staleness tracking habilitado                   │
│  └── Listo para: uat open --release TAG            │
└──────────────────────────────────────────────────────────┘
```

## Pipeline Invocation

```bash
# Pipeline completo (E14.5)
sddk uat generate \
  --requirements ./docs/ \
  --changelog CHANGELOG.md \
  --last-plan uat-plan-v1.9.0.yaml \
  --output uat-plan-v1.9.1-draft.yaml

# Con discovery de app real (E14.4)
sddk uat generate \
  --requirements ./docs/ \
  --app-url http://localhost:3000 \
  --discover \
  --output uat-plan-v1.9.1-draft.yaml

# Solo quality gate (E14.2, sobre plan existente)
sddk uat quality --plan uat-plan.yaml

# Solo UX form enrichment (E14.3, sobre plan existente)
sddk uat enrich-forms --plan uat-plan.yaml --output uat-plan-enriched.yaml

# Pipeline con approval humano (abre dashboard en modo Designer)
sddk uat generate --requirements ./docs/ --interactive --output uat-plan-approved.yaml
```

## Quality Gate Contract

El Form Quality Agent (E14.2) tiene contrato estricto:

| Severity | Comportamiento del pipeline |
|----------|---------------------------|
| BLOCKER | Para el pipeline; exige remediación antes de continuar |
| WARNING | Emite en report pero continúa; humano decide |
| SUGGESTION | Incluido en report para información |

Threshold configurable:
```bash
sddk uat quality --plan FILE --threshold WARNING  # WARNING también para el pipeline
sddk uat quality --plan FILE --threshold BLOCKER  # Solo BLOCKER para el pipeline (default)
```

## Provenance en cada artifact

Todo artifact del pipeline lleva provenance:

```yaml
# En uat-plan-draft.yaml (Stage 1 output)
provenance:
  stage: scenario-generation
  generated_by: uat-planner
  model: MiniMax-M3
  based_on:
    requirements_refs: [RF-016, RF-017]
    changelog_ref: CHANGELOG.md
    last_plan_ref: uat-plan-v1.9.0.yaml
    aam_ref: aam-fara-session-xxx.yaml  # si E14.4 se usó
  confidence: 0.85
  human_reviewed: false
  quality_report_ref: quality-report.yaml  # link al stage 3

# En approved-plan.yaml (Stage 5 output)
provenance:
  stage: human-approved
  approved_by: { id: user:421, display: "Ana" }
  approved_at: "2026-08-11T..."
  changes_from_draft: ["S-3 split into S-3a/S-3b", "added checkpoint CP-1"]
```

## Implementation

### CLI Changes
- Nuevo comando: `sddk uat generate [--requirements DIR] [--app-url URL] [--discover] [--interactive]`
- Comando existente: `sddk uat quality` (E14.2)
- Comando existente: `sddk uat enrich-forms` (E14.3)

### File changes
- `crates/sddk-cli/src/uat.rs`: nuevo subcommand `UatGenerateArgs` + pipeline orchestration
- `crates/sddk-domain/src/uat.rs`: `UatPipelineStage`, `UatPipelineReport`
- `agents/uat-planner.md`: actualizado para soportar `--pipeline` mode (recibe AAM, pasa quality, etc.)
- `agents/uat-form-quality.md` (E14.2): nuevo
- `agents/uat-ux-form.md` (E14.3): nuevo
- `agents/uat-discovery.md` (E14.4): nuevo

## Acceptance Criteria

- [ ] `sddk uat generate --requirements ./docs/ --output draft.yaml` produce un plan con provenance de Stage 1
- [ ] `sddk uat quality --plan draft.yaml` emite report con smells del E14.2
- [ ] Si `--threshold BLOCKER` (default) y hay BLOCKER smells → pipeline se detiene con mensaje claro
- [ ] El dashboard en modo Designer permite approval humano con diff visible vs. draft
- [ ] El plan aprobado tiene provenance completo: todos los stages representados
- [ ] Si `--discover --app-url URL` → E14.4 DiscoveryAgent se invoca primero
- [ ] `cargo test --workspace` verde; 0 clippy errors post-implementación
