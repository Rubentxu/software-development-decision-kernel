# Spec: E14.3 — UX Form Agent (Semantic → Optimal Interaction)

## Goal

Dado un acceptance criterion semántico (ej: "After saving, the project appears in the project list"), el UX Form Agent decide cuál es la **interacción óptima con el tester humano**: blind observation, machine check, o human confirmation. No decide QUÉ probar — eso es Test Designer — sino CÓMO preguntar para que el humano valide sin sesgo y sin trabajo redundante.

## Responsabilidad del agente

El UX Form Agent recibe:
- Un criterion: texto libre con la intención del test
- El contexto: preconditions, actor, sistema bajo test
- Restricciones: tiempo disponible, si el resultado es objetivamente verificable

Y decide:
- ¿Qué tipo de input humano? (blind_observation, yes_no, rating, text, etc.)
- ¿Qué oracles automáticos incluir? (dom, http, visual_ai, etc.)
- ¿Qué evidencia capturar? (screenshot, video, console, etc.)
- ¿Cuál es el flujo? (next, skip, goto on fail, checkpoint)

## Decision Tree (heurística del agente)

```
criterion
  │
  ├─ ¿El resultado es objetivamente verificable por máquina?
  │     ├─ SÍ → usar oracle automático (dom/http/json)
  │     │         ├─ ¿Se necesita confirmación humana?
  │     │         │     ├─ SÍ → oracle + human_confirmation
  │     │         │     └─ NO → oracle solo (sin preguntar al humano)
  │     └─ NO → ¿Es observable por el humano sin conocer el expected?
  │               ├─ SÍ → blind_observation (expected oculto)
  │               └─ NO → human_confirmation (humano evalúa sin ciego)
  │
  ├─ ¿Es criterio de UX/subjetivo? (usabilidad, claridad, diseño)
  │     └─ SÍ → human_rating con escala 1-5 + require_comment_below
  │
  └─ ¿Hay acción del usuario? (click, form submit, typing)
        ├─ SÍ → form_action con los campos relevantes
        └─ NO → instruction + expected + checks
```

## Output

El agente produce una `UatFormSpec` optimizada por scenario:

```yaml
scenario_id: S-1
title: Proyecto aparece en la lista tras guardar

form:
  items:
    - id: save-action
      kind: form_action
      instruction:
        type: instruction
        text: Haz clic en "Guardar proyecto".
      action:
        label: Guardar
        fields: []
      checks:
        - id: oracle-dom
          kind: dom
          oracle: dom
          target: "[data-project-list]"
          expected: "Contiene el proyecto guardado"
          blocking: true
          evidence_requirement:
            required: false
        - id: human-confirm
          kind: human_confirmation
          prompt: "¿El proyecto aparece en la lista?"
          visibility: visible
          blocking: false
          evidence_requirement:
            required: true
            accepted: [screenshot]

    - id: blind-verify
      kind: check
      check:
        kind: blind_observation
        prompt: "¿Qué mensaje aparece tras guardar?"
        visibility: blind
        expected: "Proyecto guardado correctamente"
        oracle:
          kind: text
          match_mode: contains
        blocking: false
        evidence_requirement:
          required: false

    - id: usability-rating
      kind: check
      check:
        kind: rating
        prompt: "¿Cómo valorarías la claridad del mensaje de confirmación?"
        scale: { min: 1, max: 5, anchors: { 1: Confuso, 3: Neutral, 5: Inmediato } }
        require_comment_below: 3
        blocking: false
```

## Decision Principles

1. **Never ask what machine knows**: si DOM/HTTP/console lo verifican, no preguntar al humano
2. **Use blind when possible**: el tester observa sin conocer el expected → reduce sesgo
3. **Evidence for critical paths**: todo FAIL en un scenario P0 requiere screenshot obligatoria
4. **Rating for UX**: criterios de usabilidad siempre con escala y comment obligatorio si baja
5. **Blocking on first failure**: P0 scenarios con oracle fallando → stop automático
6. **Checkpoint every 5 steps**: en scenarios >5 items, insertar checkpoint antes del siguiente grupo

## Implementation

### Location
- **Agent**: `agents/uat-ux-form.md` — el agente propiamente dicho

- **Integration**: invocado por `uat-planner` post-scenario-generation, pre-publish

### Prompt strategy

El agente usa few-shot examples para aprender la decisión tree:

```
Example 1:
Criterion: "The user receives a confirmation email after registration"
Decision: oracle=http (verificar email enviado) + human_confirmation
Reasoning: "El HTTP call verifica el email; el humano confirma que lo recibe en su bandeja"

Example 2:
Criterion: "The error message is helpful when login fails"
Decision: blind_observation (humano lee el mensaje sin ver expected) + rating
Reasoning: "El mensaje de error es subjetivo/usabilidad; ocultamos el texto esperado"

Example 3:
Criterion: "The workspace list displays all user's projects"
Decision: oracle=dom (contar items en DOM) + blind_observation (contar cuántos ve el humano)
Reasoning: "Coincidencia de conteo ciega: máquina y humano cuentan independientemente"
```

### Integration con Form Quality Agent

UX Form Agent recibe el `UatFormQualityReport` de E14.2 y:
- Si hay `MACHINE_OBSERVABLE` → elimina la pregunta redundante
- Si hay `SUBJECTIVE_NO_SCALE` → añade rating con escala
- Si hay `STEP_TOO_LARGE` → divide en múltiples items

## Acceptance Criteria

- [ ] Para cada criterion en un set de prueba (10 criterios variados), el agente produce una UatFormSpec
- [ ] La spec generada cumple las decision principles (1-6)
- [ ] El output pasa `validate_form_dsl()` sin errores
- [ ] Si E14.2 detecta smells, UX Form Agent los incorpora en la remediación
- [ ] El agente NUNCA genera HTML/JS — solo YAML/JSON declarativo
- [ ] La spec generada incluye provenance con: generated_by, model, based_on, confidence
