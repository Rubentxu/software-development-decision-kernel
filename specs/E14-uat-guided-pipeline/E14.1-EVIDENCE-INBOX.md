# Spec: E14.1 — Evidence Kinds + Inbox Enrichment

## Goal

Cerrar dos gaps pequeños pero concretos de la auditoría de alineación E13:
1. Añadir `video` y `annotation` a `UatFormEvidenceKind` y sus UI en `evidenceCaptureUI()`
2. Enriquecer `inboxView()` con metadata completa: est_time, preflight_checks count, human judgment count, coverage %

## Changes

### 1. Domain: `UatFormEvidenceKind` (crates/sddk-domain/src/uat.rs)

Añadir dos variantes al enum existente en línea 889:

```rust
pub enum UatFormEvidenceKind {
    Screenshot,
    Video,        // NUEVO: grabación de pantalla o viewport
    Annotation,    // NUEVO: anotación sobre screenshot (flechas, círculos, texto)
    File,
    Annotation,
    BrowserTrace,
    Console,
    Network,
    Log,
    Url,
    Clipboard,
}
```

Añadir serialización YAML/JSON consistente con las variantes existentes.

### 2. UI: `evidenceCaptureUI()` (assets/uat-dashboard/kit/components.js)

En la función `evidenceCaptureUI()`, añadir handlers para `video` y `annotation`:

**video**:
- Captura via `MediaRecorder` API del viewport o pantalla completa
- Guarda como `video/webm; codecs=vp9`
- Hash SHA-256 igual que screenshot
- Muestra preview thumbnail + duración + tamaño
- Límite configurable (default: 30 segundos)

**annotation**:
- Requiere un screenshot existente como base
- Abre un modal con canvas editable (anotación sobre imagen)
- Herramientas: flecha, rectángulo, texto libre
- Exporta como PNG overlay sobre el screenshot original
- Referencia: `{ kind: annotation, ref: sha256, based_on: sha256_del_screenshot }`

### 3. UI: `inboxView()` enrichment (assets/uat-dashboard/kit/components.js)

En `inboxView()`, por cada scenario row, mostrar:

```javascript
// Rico en metadata:
`<td class="inbox-meta">
  ${sc.est_minutes || 0}m ·
  ${preflightCount} preflight ·
  ${humanJudgmentCount} human
</td>`
```

Donde:
- `preflightCount`: `scenario.context?.preconditions?.length || 0`
- `humanJudgmentCount`: `scenario.form?.items?.filter(i => i.check?.kind in {human_observation, human_confirmation, human_rating, blind_observation})?.length || 0`
- Coverage %: `passedScenarios / totalScenarios * 100`

Además, la summary row del inbox muestra:
- Total time estimate (sum de todos los est_minutes)
- Total preflight items
- Total human judgment items
- Overall coverage %

### 4. Schema validation (crates/sddk-domain/src/uat.rs)

`validate_form_dsl()` debe aceptar `video` y `annotation` como evidence kinds válidos. No debe rechazar specs que los usen.

## Acceptance Criteria

- [ ] `uat validate` acepta plans con `evidence.kinds: [video]` y `[annotation]`
- [ ] La guided UI renderiza el input de video con `MediaRecorder` y guarda el archivo
- [ ] La guided UI permite anotar sobre un screenshot existente y guarda el PNG overlay
- [ ] El inbox muestra por cada scenario: `est_minutes`, `preflight_count`, `human_judgment_count`
- [ ] El inbox summary muestra totals y coverage %
- [ ] `cargo test --workspace` verde; 0 clippy errors
