# SPEC-049 — Goal Result, Reporting & Obligation-Completeness Contract

**Status:** Proposed

## Purpose

Guarantee that simplifying LLM interaction does not silently remove outputs or engineering discipline.

## Core invariant

```text
Fewer agent calls
        ≠
Fewer workflow obligations
```

A high-level GoalRun may consolidate orchestration but MUST preserve every mandatory result required by the selected workflow, policy and packs.

## Obligation classes

A goal can require:

### State obligations
Examples:

```text
cycle.closed
main.sha.verified
lease.released
```

### Verification obligations
Examples:

```text
tests.passed
architecture.rules.satisfied
assurance.verdict.acceptable
debt.verdict.acceptable
```

### Artifact/report obligations
Examples:

```text
proposal
spec
design
tasks
verify-report
debt-report
release-report
archive-report
archive-manifest
HTML/cockpit artifacts where required
```

### Receipt obligations
Examples:

```text
gate receipt
capability receipt
merge receipt
release receipt
approval receipt
```

### Knowledge obligations
Examples:

```text
graph projection updated
vault valid
archive linked
jurisprudence/learning persisted when policy requires
```

### Metrics obligations
Examples:

```text
cycle metrics
execution route metrics
evidence coverage
cost/token/latency
tool-use telemetry
```

## GoalResult

A GoalResult is an index and concise state summary:

```yaml
goal_result:
  goal_run_id: ...
  goal: cycle.closed
  status: succeeded
  final_snapshot_ref: ...
  obligations:
    required: 23
    satisfied: 23
    missing: 0
  reports:
    - kind: verify-report
      ref: artifact://...
    - kind: debt-report
      ref: artifact://...
    - kind: release-report
      ref: artifact://...
    - kind: archive-report
      ref: artifact://...
  receipts: [...]
  evidence: [...]
  metrics_ref: ...
  events:
    correlation_id: ...
```

It does not inline every report unless requested.

## Detailed report preservation

Existing detailed artifacts remain generated by their owning operations/packs.

Migration rule:

```text
old sequence report X
→ new GoalRun must still produce X
  OR an explicitly versioned successor with equivalent/superset semantics
```

Replacing a report requires a separate compatibility decision and migration plan.

## Agent access

The agent receives concise GoalResult by default but can retrieve:

```text
report detail
evidence detail
receipt detail
why/blocker explanation
```

without reconstructing paths manually.

## Human access

Cockpit/CLI can render the same detailed reports as before, plus an aggregated GoalRun view.

## Parity contract

For every migrated legacy sequence define a **Behavioral Parity Fixture**:

```yaml
parity:
  legacy_flow: ...
  goal: ...
  required:
    invariants: [...]
    report_kinds: [...]
    receipt_kinds: [...]
    event_families: [...]
    metrics: [...]
    blocker_cases: [...]
```

Goal migration cannot become default until parity passes.

## Superset allowed

The new goal path may produce additional evidence/telemetry.

It may not silently omit mandatory legacy output.

## Failure behavior

If all operational steps ran but a required report failed to persist:

```text
GoalRun != succeeded
```

The result is `blocked` or `failed` according to the report's policy.

## Efficiency accounting

Savings are measured separately:

```text
agent calls
CLI/process calls
tokens
latency
```

They never alter the completeness requirement.

## Design consequence

The optimization target is:

> **same or stronger engineering outcome with lower interaction overhead.**
