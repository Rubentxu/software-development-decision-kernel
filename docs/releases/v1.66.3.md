## Summary

Patch bump that closes the count-workspace parser regression and the
INC-DEBT-017 cycle_exists drift. No public API changes; no breaking
changes; binary fully interchangeable with v1.66.2 except for the two
fixes below.

## Fixed

### `sddk dev test count-workspace` reports accurate totals (cycle-13)

The subcommand emitted `total_workspace_tests: 0` on every invocation
because the JSON-event parser (built against `cargo --message-format=json
--no-run`) silently produced no events on cargo 1.91. Replaced with a
pure-function text-line aggregator (`parse_cargo_test_output`, regex
`^test result:\s+ok\.\s+(\d+)\s+passed`) plus 8 unit tests covering
empty input, dedup, FAILED-excluded, leading whitespace, ground-truth
1739-line scale, multi-binary, single-binary, and no-running-lines
scenarios.

Live binary now reports the correct totals:

```
$ sddk dev test count-workspace
total_workspace_tests: 1747
test_binaries: 79
```

Closes `INC-CYCLE-13-APPLY-TEST-COUNT-MISREPORT` (P2/medium).
Closes finding `F-C13-COUNT-IMPL-BUG`, `F-C13-COUNT-TEST-QUALITY`,
and `F-C13-APPLY-DISCIPLINE-VIOLATED` from the predecessor cycle's
verification.

## Refactored

### `port_contracts.rs` LOC budget moved to total-module (cycle-13)

The `mk_*` builders that power `port_contracts.rs` were extracted to
`crates/sddk-engine/tests/common/port_contracts_helpers.rs`. Per-file
LOC budget superseded by total-module-sum budget per ADR-0048; the
contract file no longer accumulates LOC when new scenarios land.

Closes `INC-CYCLE-13-LOC-OVERAGE` (P2/medium).

## Documented

### `apply-progress.yaml` mandates live subcommand as source of truth (cycle-13)

Apply reports may no longer recalculate or estimate
`total_workspace_tests`. The live binary output is the canonical
source; the apply envelope must include the verbatim stdout byte-for-byte
to pass REQ-C13-APPLY-DISCIPLINE.

### `INC-DEBT-017` closed — cycle_exists helper (v1.66.2) completes contract

INC-DEBT-017 documented a drift left out-of-scope by `fix/gap6-foreign-cycle-typed-error`
(v1.66.1): when the storage layer opened a `sddk-cycles` row for a
foreign project, it surfaced as `STORAGE_DATABASE` (FK constraint) instead
of `STORAGE_NOT_FOUND`. The `cycle_exists` storage helper + 4 pre-checks
in acquire/renew/release/status (delivered in v1.66.2 via
`fix/storage-cycle-lease-pre-existence-check`) close that gap. The
complete typed-error contract for `sddk cycle lock` is now:

- `foreign project → STORAGE_CYCLE_PROJECT_MISMATCH` (v1.66.1)
- `own-project-missing → STORAGE_NOT_FOUND` (v1.66.2)
- no more `STORAGE_DATABASE` FK leak.

Closes `INC-DEBT-017` (P3/low).
