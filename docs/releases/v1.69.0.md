# v1.69.0 — 2026-09-02

## Summary

v1.69.0 es un release **MINOR** que generaliza **GAP-UX-1** (introducido en
v1.66.6 / cycle-51) a todo error user-facing del CLI: cada
`StorageError` y `EngineError` ahora cita el comando EXACTO a ejecutar
siguiente, con parámetros rellenados cuando es posible. La cobertura
anterior solo aplicaba a `EngineError`; cycle-54 extiende la tabla a
`StorageError::NotFound` (con entity-aware hints para `cycle` /
`gate receipt` / catch-all) y a `StorageError::LeaseConflict`
(cycle_id incluido en el comando sugerido). El audit grep del CLI source
devuelve 0 hits de frases genéricas (`create the record|fix the reference`).

Junto a la generalización de hints, v1.69.0 cierra el ciclo de los 4
follow-ups del debt report de v1.68.0 (CPL-01 schema-drift guard,
CPL-02 atomic-swap triplicado, OVG-02/03 dead fields, OVG-04 INC-DEBT-020
prefix tokens), refactoriza `swap_current_to` para colapsar 3 sitios de
duplicación, y resuelve **WARN-001** del verify report migrando
`validate_cycle_project` a construir `sddk_domain::StorageError` (cerrando
el leak de hints que aún mostraba el recovery genérico para cycle-ids
malformados).

> **Why MINOR**: cycle-54 extiende una capability user-visible documentada
> (`GAP-UX-1`) y surface nuevos campos en `FrontierEntryOutput` JSON
> (consumidos por agents leyendo `sddk cycle next --format json`). Ambos
> ejes son user/agent-visible, consistentes con los juicios MINOR de
> cycle-52 (1.66.6→1.67.0) y cycle-53 (1.67.0→1.68.0).

## What's new

### GAP-UX-1 generalized — every user-facing error cites the EXACT command

`StorageError::recovery()` en `crates/sddk-domain/src/models/storage_error.rs`
ahora devuelve hints accionables keyed by error variant AND entity:

| Variant | Hint |
|---|---|
| `NotFound { entity: "cycle", .. }` | `run \`sddk cycle start --scope .\` to create a new cycle, or \`sddk cycle rebuild --cycle <id>\` if the cycle exists in ledger events` |
| `NotFound { entity: "gate receipt", .. }` | `evaluate the gate with \`sddk cycle evaluate-gate\` before the transition` |
| `NotFound { .. }` (catch-all) | `ensure the record exists before operating on it` |
| `LeaseConflict { cycle_id, .. }` | `run \`sddk cycle lock inspect --cycle {cycle_id}\` to see the current lease, then \`sddk cycle lock release --cycle {cycle_id}\` to release it` |

`EngineError::recovery()` (`crates/sddk-engine/src/lib.rs:1682`) cita la
invocación exacta `sddk cycle evaluate-gate --gate <name> --transition <id>`
con parámetros rellenados desde el error context (gate name, transition id,
receipt id). 26 variantes de `EngineError` actualizadas.

Audit gate (CLI scope — el criterio de aceptación explícito):

```
$ rg -n "create the record|fix the reference" crates/sddk-cli/src/
(none - 0 hits)
```

Las frases genéricas siguen presentes en
`sddk_storage::StorageError::recovery()` como fallback del storage crate
(ADR-0015 ARCH003 waiver); el downcast chain de la CLI prefiere
`sddk_domain::StorageError` cuando está presente.

### `FrontierEntryOutput` JSON gains `from_phase` / `to_phase` / `closes_cycle`

`crates/sddk-cli/src/cycle.rs:1813` añade tres campos a
`FrontierEntryOutput`, surfaced desde los previously-unconsumed
`FrontierEntry.from.phase` / `FrontierEntry.to.phase` /
`FrontierEntry.to.status` (OVG-02/03 del debt report de v1.68.0):

```json
{
  "frontier": [
    {
      "transition_id": "phase.build.verify",
      "to": { "phase": "OPEN/verify", "status": null },
      "requires_met": true,
      "from_phase": "OPEN/build",
      "to_phase": "OPEN/verify",
      "closes_cycle": false,
      "unmet_gates": [],
      "unmet_requirements": []
    }
  ]
}
```

Agents que leen `sddk cycle next --format json` ahora reciben:

- `from_phase` — la fase del ciclo que la transición deja (`Option<String>`)
- `to_phase` — la fase del ciclo que la transición entra (`Option<String>`)
- `closes_cycle` — boolean flag cuando `to.status == Closed`

Los 8 tests existentes de frontier + el JSON-shape stability test
(`cycle_next_json_output_has_stable_shape`) se actualizaron; sin breakage
para consumers JSON.

## WARN-001 leak closure (live stderr proof)

Antes de cycle-54 (WARN-001 del verify report de v1.68.0):

```
$ sddk cycle lock acquire --owner test --cycle "malformed-no-prefix"
error[STORAGE_NOT_FOUND]: cycle not found: malformed-no-prefix
  recovery: create the record or fix the reference   ← GENERIC
```

Después de cycle-54 (commit `d93e2ce` migra `validate_cycle_project` para
que construya `sddk_domain::StorageError::NotFound { entity: "cycle", .. }`):

```
$ sddk cycle lock acquire --owner test --cycle "malformed-no-prefix"
error[STORAGE_NOT_FOUND]: cycle not found: malformed-no-prefix
  recovery: run `sddk cycle start --scope .` to create a new cycle,
            or `sddk cycle rebuild --cycle <id>` if the cycle exists in ledger events
```

Mismo path para `cycle lock status` / `cycle lock renew` / `cycle lock
acquire` — los 4 call sites de `validate_cycle_project` ahora rutean por
el actionable hint del domain layer.

El follow-up commit `9d7f548` revierte solo la migración de
`CycleProjectMismatch` (que se mantiene en
`sddk_storage::StorageError` para preservar el error code
`STORAGE_CYCLE_PROJECT_MISMATCH` que 4 integration tests assertean). La
migración de `NotFound` — y el cycle-specific hint — se preserva.
