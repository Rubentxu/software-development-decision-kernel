# v1.68.0 — 2026-09-02

## Summary

v1.68.0 es un release **MINOR** que cierra el segundo slice de **Epic SD
(State-Driven CLI)**: `sddk cycle next` es el advisor proactivo de ciclo,
derivado del grafo de transiciones DECLARADAS en `workflow.yaml` — cero
secuencias hardcodeadas en el código de producción. La proof D1 (sin
topología canónica en memoria) la demuestra el **diamond fixture** del test
`frontier_for_state_diamond_topology` (engine/lib.rs:2050-2080): si el
engine hardcodease el path A-min, el diamond (4 transiciones, dos ramas
paralelas `spec.a`/`spec.b` que convergen en `build`) fallaría al exigir 2
entradas de frontera desde `specify` con ambos ids — y pasa.

Junto al advisor, v1.68.0 cierra **INC-DEBT-020** (heredado de cycle-53):
`sddk dev update --prune-only` re-apunta el symlink `current` a la versión
más nueva retenida, de modo que `sddk dev doctor` mantiene `bundle_coherence:
present` tras el prune (antes: symlink colgando → doctor FAIL con cualquier
bundle vigente). El modo dev-link sin flags de prune preserva su comportamiento
previo.

## What's new

### `sddk cycle next` — frontier advisor

Subcomando nuevo en `crates/sddk-cli/src/cycle.rs:482` (`CycleCommand::Next`).
Dos formas de salida:

**Humano** (por defecto, sin flags):

```text
$ sddk cycle next
Cycle:   kernel-cycle-53-frontier-advisor
Phase:   OPEN/build
Node:    apply
Next steps (frontier):
  ✓ verify                  → target_phase: OPEN/verify   (requires: met)
  ⊘ remediate               → target_phase: REMEDIATING/build   (requires: unmet — gate: regression-and-build)
                            hint: sddk cycle evaluate-gate --transition release.complete --gate regression-and-build ...
```

**JSON** (`--json`) con envelope estable:

```json
{
  "cycle": "kernel-cycle-53-frontier-advisor",
  "node": "apply",
  "phase": "OPEN/build",
  "frontier": [
    {
      "transition_id": "phase.build.verify",
      "to": { "phase": "OPEN/verify", "status": null },
      "requires_met": true,
      "unmet_gates": [],
      "unmet_requirements": []
    },
    {
      "transition_id": "phase.build.remediate",
      "to": { "phase": "REMEDIATING/build", "status": null },
      "requires_met": false,
      "unmet_gates": ["regression-and-build"],
      "unmet_requirements": [],
      "hint": "sddk cycle evaluate-gate --transition release.complete --gate regression-and-build --cycle <id>"
    }
  ]
}
```

Transiciones bloqueadas se marcan `requires_met: false` con `unmet_gates` /
`unmet_requirements` poblados y un hint ejecutable apuntando a `evaluate-gate`.
Ciclos terminales devuelven frontier explícitamente vacía con reason
`cycle_terminal` (no silencioso — el usuario ve que el advisor terminó).

### Derivación desde el workflow DECLARADO

`frontier_for_state` (`crates/sddk-engine/src/lib.rs:1533`) es una función
pura: `(WorkflowManifest, CycleManifest, cycle_id, &dyn Ledger) -> Result<Vec<FrontierEntry>, EngineError>`.
No lee artefactos pre-calculados; reconstruye el nodo del ledger
(`engine.replay_cycle` → `replay_state`) y cruza con `workflow.transitions`.
El estado del ciclo siempre viene del replay, no de snapshots stale.

### Zero-arg inference heredado de v1.67.0

`cycle next` se monta sobre `resolve_cycle_context` (v1.67.0, cycle.rs:140),
así que hereda la inferencia zero-arg cuando hay un único lease activo.
`--no-infer` opt-out sigue disponible para automation.

## Fixed

### INC-DEBT-020 — `sddk dev update --prune-only` re-apunta `current`

Antes de v1.68.0:

```text
$ sddk dev update --prune-only --keep 1
removed 1, kept 1.67.0
$ sddk dev doctor
binary.bundle_coherence: ABSENT  ← current symlink dangling a 1.66.6 (ya borrada)
```

Después de v1.68.0:

```text
$ sddk dev update --prune-only --keep 1
removed 1, kept 1.67.0
$ sddk dev doctor
binary.bundle_coherence: present  ← current re-apunta a 1.67.0 (newest kept)
```

Cambios en `crates/sddk-cli/src/dev/update.rs`:

- Nuevo helper `repoint_current_to_newest(framework_dir, newest_version)`
  (update.rs:127) que ejecuta el swap atómico (`tmp + remove_file x2 +
  symlink + rename`) del `current` para apuntar al newest retained.
- Llamado desde ambas ramas prune (`--prune-only` en update.rs:315 y
  `--prune` normal en update.rs:344).
- Modo dev-link (sin flags de prune) preservado por guard
  `if args.root.as_os_str() == "." && !args.prune && !args.prune_only`
  (update.rs:282) — no toca el symlink.

3 tests nuevos cubren las tres ramas (`prune_repoint_current_after_prune_keeps_valid_target`,
`update_prune_only_repoints_current_to_newest_dev_link_mode`,
`s_dev_link_preserved_without_prune_flags_keeps_dev_link_target`) más 2
regresiones en el helper (`repoint_current_skips_nonexistent_version_dir`,
`repoint_current_to_newest_symlink_swap_is_atomic`).
