# v1.169.0 — 2026-09-13 (DRAFT)

> **Estado**: draft de apply (WU-C15-8). SHAs y contadores finales se
> completan en el paso de release. El bump de versión y el flujo completo
> (`scripts/release.sh`) ocurren fuera de apply.

## Summary

v1.169.0 es un release **BREAKING (MINOR + breaking changes internas)** que
completa la remoción física de la tabla legacy `ledger_events`
(ciclo `p-63676b11dc0ef88f/c15-ledger-removal-2026-09-13`, decision C1.5):
schema v20 la elimina (`MIGRATION_20`), el trait `Ledger` pierde
`load_all_ledger_events`, la surface de authority `WritableSurface::LedgerEvents`
desaparece (12 → 11 surfaces) y la allowlist de compatibilidad
`legacy-compat-allowlist.yaml` se borra con todos sus ratchets C1.3/C1.4.
El stream canónico `events_v1` queda como única autoridad de eventos de
dominio (AGENTS.md §2.7, single canonical authority).

## Breaking changes

### Schema: DROP TABLE `ledger_events` (v20)

- `MIGRATION_20` ejecuta `DROP TRIGGER IF EXISTS ledger_events_no_update`,
  `DROP TRIGGER IF EXISTS ledger_events_no_delete`,
  `DROP INDEX IF EXISTS ledger_events_cycle_sequence_idx`,
  `DROP TABLE IF EXISTS ledger_events` (todo `IF EXISTS`, idempotente).
- `LATEST_SCHEMA_VERSION` 19 → 20. El DDL de `MIGRATION_1` ya no crea la
  tabla (repositorios fresh nacen sin ella).
- **Pre-upgrade obligatorio**: `sddk ledger export` para preservar el
  corpus legacy si se necesita recuperación (el inventario
  `pre-drop-export-receipt.json` del ciclo archiva el estado pre-drop de 10 DBs
  locales, todas sin tabla legacy: nada que preservar).
- **Ventana de downgrade rota (aceptada)**: una DB migrada a v20 no puede
  volver a binarios ≤ v1.168.x sin perder la tabla (expected: la surface
  murió; el downgrade path no se mantiene).

### Trait `Ledger`: `load_all_ledger_events` fuera

- `sddk_domain::ports::Ledger` elimina el método
  `load_all_ledger_events` (R-15-003). Toda lectura de eventos es vía
  `list_events` / `list_cycle_events` / `list_frame_events` /
  `list_events_after` (vista canónica) o `SqliteEventStore` (`events_v1`).
- Los wrappers deprecated `insert_cycle_with_event`,
  `update_cycle_with_event` (ahora métodos del trait, de-deprecated),
  `append_event` (eliminado) y `release_cycle_lease` (renombrado a
  **`release_lease_with_event`**) cambian de superficie.
- `Storage::emit_canonical_event` pasa a `pub` (vía canónica de seed para
  tests/testkit).
- `StorageError::LegacyDomainWriteForbidden` eliminada (sin sujeto).

### Authority: `WritableSurface::LedgerEvents` fuera

- El enum pierde la variante (12 → 11); `WRITABLE_SURFACE_MATRIX` pierde su
  fila deny-all y `default_policy_for_surface` pierde el arm
  `"ledger_events"`. La denegación pasa de runtime a **compile-time**:
  usar la surface retirada es un error de compilación.

## What's new

### Ratchet DDL-absence (R-15-006)

`crates/sddk-cli/tests/arch_ratchet_mutations.rs`:
- `ledger_events_ddl_is_absent_from_schema` — escanea `migrations.rs`
  comment-stripped (Rust + SQL) y exige que toda ocurrencia del nombre sea
  una línea `DROP` (MIGRATION_20). Sin allowlist ni exenciones.
- `scanner_detects_injected_legacy_ddl` — mutation self-check: un
  `CREATE TABLE` re-añadido en un `MIGRATION_*` futuro o un `INSERT INTO`
  sintético se detectan; menciones en comentario no.
- Los ratchets WU-C2 (conf09) y WU-C3 (conf09b) quedan intactos.

### Suite chain-integrity canónica

`crates/sddk-storage/tests/cross_ledger_consistency.rs` reescrita: ya no
compara "dos ledgers" (no hay dos). Ahora prueba la integridad del stream
único: cadena verificable multi-ciclo (`verify_ledger`), detección de
tampering (mutación SQL rompe la verificación), y append-only real
(triggers `events_v1_no_update/no_delete` rechazan UPDATE/DELETE).

### Fixtures canónicos

`canonical_parity`, `ledger_watch`, `legacy_ledger_migration`,
`sqlite_storage`, `properties` y tests de engine/cli migrados al seed
canónico (`emit_canonical_event` pub / `SqliteEventStore`). Los fixtures
con seed SQL legacy desaparecen junto a la tabla.
