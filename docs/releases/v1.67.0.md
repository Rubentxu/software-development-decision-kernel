# v1.67.0 — 2026-09-02

## Summary

v1.67.0 is a MINOR release that ships the first slice of **Epic SD (State-Driven
CLI)**: when cycle state is unambiguous, the user no longer has to repeat
`--root/--scope/--cycle` for every command. The `sddk cycle <verb>` family infers
those arguments from the project marker and the active cycle lease; when state
is ambiguous or absent, the CLI emits a typed error listing the candidates with
ready-to-paste commands. This is the deliverable from
`docs/sddk-decision-kernel-architecture/02-roadmap/RESEARCH/state-driven-cli/RESEARCH.md`
(slice 1 of 2 — slice 2 / cycle-53 ships the frontier advisor).

## What Changed

### Zero-arg inference when state is unambiguous

`resolve_cycle_context` is now the single resolver for the cycle family
(`status`, `transition`, `rebuild`, `artifacts-dir`, `lock acquire/renew/release`,
`supersede`, `replan`, `lock-status`, `evaluate-gate` — 11 call sites in
`crates/sddk-cli/src/cycle.rs`). When invoked from a project marker directory
(`.sddk/`, `.git/`, or `AGENTS.md` present in an ancestor), the CLI:

1. Walks up to find the project root (`walk_up_for_project_marker`).
2. Resolves `project_id` from `.sddk/project.toml`.
3. Lists active cycle leases for that project via a new read-only trait method
   `Ledger::list_active_cycle_leases_for_project`.
4. If exactly one active lease exists → use it.
5. If zero leases → `InferenceError::NoActiveCycle` with hint:
   `sddk cycle start --root <inferred> --scope . --name <name>`.
6. If multiple leases → `InferenceError::AmbiguousCycle` listing candidates
   (cycle_ids + owners + expiry) and one ready-to-paste command per candidate:
   `sddk cycle status --cycle <id>`.
7. If no project context → `InferenceError::NoProjectContext` pointing to
   `sddk project resolve` or `sddk init`.

### Explicit args keep precedence

`--root`, `--scope`, and `--cycle` remain fully supported and short-circuit
inference. When all three are explicit, no storage read happens
(`RuntimeContext::open` defers the deferred defaults via `unwrap_or`).

### `--no-infer` opt-out

For automation, scripts, and tests that prefer the old "always explicit" shape,
`--no-infer` is the escape hatch. With `--no-infer`, missing required args yield
`InferenceError::ExplicitRequired` listing `--root/--scope/--cycle`.

## Known Limitations (carry-over warnings from verify)

1. **Pre-existing flaky test under workspace parallelism.** `cli_dev_install_default_layout_is_executable_and_verify_passes` fails under
   `cargo test --workspace --locked` (HTTP port collision / shared fixture),
   passes solo (`cargo test -p sddk-cli --test cli <test>`). Pre-existing
   infra noise — not introduced by cycle-52.

2. **No runtime cycle record for this cycle.** The cycle was applied
   filesystem-artifacts-only; there is no CLI-tracked `cycle.start` row in
   the project's storage workspace. `sddk cycle status --cycle kernel-cycle-52-context-inference`
   returns `STORAGE_NOT_FOUND`. This is the same cold-start limitation as
   cycle-51; **the `archive-manifest.md` is the ground-truth durable record
   of cycle closure** (role unchanged by v1.67.0; see `AGENTS.md §8` for the
   rationale).
