# Software Alignment — bounded context overview

## Mission statement

**Software Alignment helps understand whether observed software remains coherent with its intent, decisions and selected paradigms; its outputs are evidence and contextual advice, never imperative instructions.**

## Inputs

- KnowledgeAssertions / Cards;
- Evidence from Git/tests/static/runtime providers;
- Decision Memory;
- ArchitecturalIntent;
- selected AlignmentLenses.

## Outputs

- AlignmentAssessment;
- AlignmentTension;
- ImprovementOpportunity;
- ContractViolation only for explicit contracts;
- contradictions/unknowns;
- workbook projections;
- requested evidence/deepening hints.

## Boundary

Alignment cannot mutate source, approve, grant authority or decide release. This prevents a heuristic such as SOLID/SRP from becoming accidental governance.
