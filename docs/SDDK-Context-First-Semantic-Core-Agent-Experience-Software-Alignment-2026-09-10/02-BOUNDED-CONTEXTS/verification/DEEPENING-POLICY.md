# Deepening policy

## Inputs

`risk × impact × uncertainty × freshness × persistence × evidence_coverage × analysis_cost`.

## Niveles

```text
D0 card only
D1 provider summary/outline
D2 graph/dependency slice
D3 AST/symbol source
D4 raw file/module
D5 multi-file/context review
D6 runtime scenario
```

Verify prioriza coste bajo y changed scope. DebVerify puede usar muestreo estratificado y ampliar sólo donde la ganancia de información lo justifique.

El budget forma parte del receipt para explicar por qué algo quedó NOT_EVALUATED.
